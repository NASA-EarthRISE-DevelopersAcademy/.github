# NASA EarthRISE Developers Academy

Project teams use GitHub to organize work, document decisions, review changes, and maintain a clear record of project progress.

## Using GitHub in Your Project

| GitHub feature | How to use it |
|---|---|
| **README** | Describe the project, installation process, data, methods, outputs, and current status. |
| **Issues** | Track tasks, bugs, questions, decisions, and project deliverables. |
| **Branches** | Develop changes without modifying the stable `main` branch directly. |
| **Commits** | Record focused, understandable changes to the project. |
| **Pull requests** | Review and discuss changes before merging them into `main`. |
| **Projects** | Organize Issues and pull requests by status, milestone, or workstream. |
| **Actions** | Run automated checks, tests, builds, and documentation deployments. |

### Recommended Workflow

1. Read the repository README and contribution guidance.
2. Create or claim an Issue describing the work.
3. Create a branch for the Issue.
4. Make focused changes and commits.
5. Open a pull request and link the Issue.
6. Respond to review feedback.
7. Merge the pull request after approval.
8. Close the completed Issue.

Use `Closes #<issue-number>` in the pull request description when merging the pull request should automatically close the related Issue.


## Project Repositories

Project repositories are private and available according to each participant’s team and repository permissions.

[Browse the organization repositories](https://github.com/orgs/NASA-EarthRISE-DevelopersAcademy/repositories)


## General Expectations

- Keep substantial work connected to an Issue or documented project objective.
- Do not commit passwords, credentials, access tokens, restricted data, or sensitive information.
- Document software, environment, and data requirements.
- Prefer reproducible workflows.
- Keep project questions and technical decisions in Issues or pull requests so they remain available to the team.
